Aula 4 · 15 min

Ciclo de vida: getTools, toolchange, AbortSignal e cancelamento

Ferramenta não é para sempre: a página registra quando a função existe e remove quando sai de cena. Na spec de 16/10/2026 não há unregisterTool; quem remove é o signal de um AbortController. E quem chama pode cancelar uma execução no meio. Nesta aula você vê o ciclo inteiro e os eventos que o navegador dispara.

Começar a aula

Nesta aula você vai

  1. 1Registro com signal e o evento toolchange
  2. 2Remover com abort(): o lugar do antigo unregisterTool
  3. 3Cancelar uma execução: signal no execute e no executeTool
  4. 4toolactivated e toolcancel: nativo dispara, polyfill não

Objetivo: registrar, listar, remover com AbortSignal e cancelar uma execução, sabendo quais eventos o navegador dispara em cada passo.

01 · O ciclo de uma ferramenta

Clique em cada passo.

Registrar de novo quando a função voltar (outra rota, outro estado)
Doc do Chrome: window.ontoolactivated e window.ontoolcancel não têm suporte desde o 156. Ouça no document.modelContext.

Medido em 19/10/2026: o Chromium 156 dispara os três eventos; o polyfill 6.0.3 só toolchange.

02 · O ciclo em código

Trecho de kit/scripts/ciclo.mjs (roda dentro da página). Dois controllers: um para o registro, outro para a chamada.

Trecho simplificado · kit/scripts/ciclo.mjs
const registro = new AbortController();
await mc.registerTool({
  name: 'tarefa_lenta', description: 'Leva 2 segundos. Existe só para ensinar cancelamento.',
  async execute(_, { signal }) {
    return new Promise((ok, falha) => {
      const t = setTimeout(() => ok({ terminou: true }), 2000);
      signal.addEventListener('abort', () => { clearTimeout(t); falha(new DOMException('cancelada', 'AbortError')); });
    });
  }
}, { signal: registro.signal });

const t = (await mc.getTools()).find(x => x.name === 'tarefa_lenta');
const chamada = new AbortController();
setTimeout(() => chamada.abort(), 100);
try { await mc.executeTool(t, {}, { signal: chamada.signal }); }
catch (e) { /* AbortError */ }

registro.abort();   // remove a ferramenta: não existe unregisterTool
Terminal · ciclo no nativo e no polyfill

Mesma sequência nos dois. A diferença está na linha "eventos": só o nativo dispara toolactivated e toolcancel.

Se o execute não ouve signal, o cancelamento rejeita a chamada, mas o trabalho continua: o setTimeout dispara, o fetch completa, a reserva acontece. Em ferramenta com efeito, confira signal.aborted antes de gravar.

03 · Onde registrar e onde abortar

Mesma regra em qualquer framework: registrar no início, abortar no fim.

1. Página

Registre depois de a regra estar pronta e aborte no pagehide.

É o que iniciarWebMCP faz no kit.

KitaddEventListener('pagehide', () => pagina.abort(), { once: true })

2. Rota

Ferramenta de uma tela só existe enquanto a tela está montada.

Trocou de rota: abort() e registre as da tela nova.

3. Componente

Em React, registre no efeito e aborte no cleanup; o modo estrito monta duas vezes e o nome repetido daria InvalidStateError.

O padrão vale para outros frameworks; a aula 7 mostra o modelo.

4. Lote

Se a terceira de quatro falha, as duas primeiras ficam penduradas.

O registrar() do kit usa um controller por lote e aborta tudo na falha.

06 · Em três frases

RemoverSignal no registro e abort() quando a função sai de cena; não existe unregisterTool.
CancelarSignal no executeTool; o execute ouve o próprio signal e para.
Eventostoolchange, toolactivated e toolcancel no document.modelContext; o polyfill só dispara o primeiro.
