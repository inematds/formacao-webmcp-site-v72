Lesson 1 · 12 min

WebMCP today: the Oct 16, 2026 draft, origin trial, flag, and who backs it

WebMCP lets a page hand tools to an agent in the browser. As of Oct 19, 2026, it is a Community Group draft, tested in an origin trial in Chrome and Edge, with Mozilla neutral and WebKit opposed. In this lesson you check the spec date with one command and learn to read the status without falling for a promise.

Start the lesson

In this lesson you will

  1. 1What a Draft Community Group Report is, and what it is not
  2. 2Origin trial 149–156, the local flag, and the missing stable date
  3. 3Who backs it, who is neutral, and who opposes it, with dates
  4. 4One command that checks the date and the API name in the spec

Goal: place WebMCP as of Oct 16, 2026 (CG draft, origin trial 149–156, local flag, backers and objections) and check the spec date with a command.

01 · Where WebMCP stands on Oct 19, 2026

Click each step.

Mozilla: neutral (Aug 3, 2026). WebKit: opposed. Without those two, no site can count on WebMCP in every browser.

A draft with a date, a trial with a deadline, and no stable date: that is why the course teaches you to prepare the page with detection and fallback.

02 · How to read the status without falling for a promise

Four questions, always with a date.

1. Which document?

A Community Group spec is a draft from an open group. It is not a W3C standard.

Read the spec's subtitle: the type and the date are at the top.

On October 19, 2026Draft Community Group Report, 16 October 2026.

2. Which browser?

An origin trial works for one domain with a token and has a set end date. A flag only works on your machine.

Neither one reaches the average visitor without you doing something.

ChromeOrigin trial 149–156; flag #enable-webmcp-testing for localhost.

3. Who is against it?

Standards positions tell you whether another engine plans to implement it.

WebKit opposed it, citing API design, duplication, i18n, portability, privacy, and security.

PositionsMozilla #1412: neutral (Aug 3, 2026). WebKit #670: oppose.

4. What changes?

The surface name, the declarative API, annotations, exposedTo, and the return shape can change.

Keep the spec date in your code, like the comment in the kit.

Already changednavigator.modelContext → document.modelContext (PR #177, May 19, 2026).

03 · Check the date and the API name in the spec itself

It downloads the spec, strips the tags, and counts. If the date is different, the spec changed: reread what changed before you continue the course.

Terminal · spec date and API name
curl -s https://webmachinelearning.github.io/webmcp/ | sed 's/<[^>]*>//g' > /tmp/webmcp-spec.txt
tr -s ' \n' ' ' < /tmp/webmcp-spec.txt | grep -o "Draft Community Group Report, [0-9]* [A-Z][a-z]* [0-9]*" | head -1
echo "document.modelContext: $(grep -c 'document.modelContext' /tmp/webmcp-spec.txt) linhas"
echo "navigator.modelContext: $(grep -c 'navigator.modelContext' /tmp/webmcp-spec.txt) linhas"
echo "unregisterTool: $(grep -c 'unregisterTool' /tmp/webmcp-spec.txt) linhas"
Example from the repository
Draft Community Group Report, 16 October 2026
document.modelContext: 16 linhas
navigator.modelContext: 0 linhas
unregisterTool: 0 linhas

16 lines mention document.modelContext; none mention navigator.modelContext or unregisterTool. To remove a tool, the spec uses the signal of an AbortController (lesson 4).

A tutorial that uses navigator.modelContext, unregisterTool, provideContext, or clearContext predates May 2026 (the switch to document happened on 05/19/2026): none of those names exist in the 10/16/2026 spec. The same count above (0 lines) is your test before you copy code from a blog.
