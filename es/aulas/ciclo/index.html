Clase 4 · 15 min

Ciclo de vida: getTools, toolchange, AbortSignal y cancelación

Una tool no es para siempre: la página la registra cuando la función existe y la quita cuando sale de escena. En la spec del 16/10/2026 no existe unregisterTool; quien la quita es el signal de un AbortController. Y quien llama puede cancelar una ejecución a la mitad. En esta clase ves el ciclo completo y los eventos que dispara el navegador.

Empezar la lección

En esta lección vas a

  1. 1Registro con signal y el evento toolchange
  2. 2Quitar con abort(): el lugar del antiguo unregisterTool
  3. 3Cancelar una ejecución: signal en execute y en executeTool
  4. 4toolactivated y toolcancel: el nativo los dispara, el polyfill no

Objetivo: registrar, listar, quitar con AbortSignal y cancelar una ejecución, sabiendo qué eventos dispara el navegador en cada paso.

01 · El ciclo de una tool

Haz clic en cada paso.

Registrar de nuevo cuando la función vuelva (otra ruta, otro estado)
Doc de Chrome: window.ontoolactivated y window.ontoolcancel no tienen soporte desde el 156. Escucha en document.modelContext.

Medido el 19/10/2026: Chromium 156 dispara los tres eventos; el polyfill 6.0.3 solo toolchange.

02 · El ciclo en código

Fragmento de kit/scripts/ciclo.mjs (corre dentro de la página). Dos controllers: uno para el registro, otro para la llamada.

Fragmento simplificado · kit/scripts/ciclo.mjs
const registro = new AbortController();
await mc.registerTool({
  name: 'tarefa_lenta', description: 'Leva 2 segundos. Existe só para ensinar cancelamento.',
  async execute(_, { signal }) {
    return new Promise((ok, falha) => {
      const t = setTimeout(() => ok({ terminou: true }), 2000);
      signal.addEventListener('abort', () => { clearTimeout(t); falha(new DOMException('cancelada', 'AbortError')); });
    });
  }
}, { signal: registro.signal });

const t = (await mc.getTools()).find(x => x.name === 'tarefa_lenta');
const chamada = new AbortController();
setTimeout(() => chamada.abort(), 100);
try { await mc.executeTool(t, {}, { signal: chamada.signal }); }
catch (e) { /* AbortError */ }

registro.abort();   // quita la tool: no existe unregisterTool

Misma secuencia en los dos. La diferencia está en la línea "eventos": solo el nativo dispara toolactivated y toolcancel.

Si el execute no escucha signal, la cancelación rechaza la llamada, pero el trabajo continúa: el setTimeout se dispara, el fetch se completa, la reserva ocurre. En una tool con efecto, revisa signal.aborted antes de guardar.

03 · Dónde registrar y dónde abortar

Misma regla en cualquier framework: registrar al inicio, abortar al final.

1. Página

Registra cuando la regla ya esté lista y aborta en pagehide.

Es lo que hace iniciarWebMCP en el kit.

KitaddEventListener('pagehide', () => pagina.abort(), { once: true })

2. Ruta

Una tool de una sola pantalla existe solo mientras la pantalla está montada.

Cambió la ruta: abort() y registra las de la pantalla nueva.

3. Componente

En React, registra en el efecto y aborta en el cleanup; el modo estricto monta dos veces y el nombre repetido daría InvalidStateError.

El patrón sirve para otros frameworks; la clase 7 muestra el modelo.

4. Lote

Si la tercera de cuatro falla, las dos primeras quedan colgadas.

El registrar() del kit usa un controller por lote y aborta todo si hay una falla.

06 · En tres frases

QuitarSignal en el registro y abort() cuando la función sale de escena; no existe unregisterTool.
CancelarSignal en el executeTool; el execute escucha su propio signal y se detiene.
Eventostoolchange, toolactivated y toolcancel en el document.modelContext; el polyfill solo dispara el primero.
